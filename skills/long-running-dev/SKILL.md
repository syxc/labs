# 给任务定下证据

AI 自动干活，最容易翻车的地方：**做完了不知道对不对**。

这一步、这个任务到底算不算完成，没有**证据**。没有证据，就只剩「应该没问题」「我改的应该没错」——往下走就把别处改坏了，或者一直在原地打转。

## 核心就一句

**动手之前，先定下证据：这件事做完没，拿什么证明？**

证据要具体到能跑、能看、能读的东西——一条命令、一个数、一张图、一段输出。定得出来，做完就拿它对；定不出来，说明这件事还没想清楚，先把证据定出来再动手。

## 好证据的两个维度

一个能用的完成标准，要在两个轴上都立得住：

- **清不清晰**：能区分做完和没做完。「P99 < 200ms」清晰，「优化性能」不清晰。
- **要求多高**：逼出多少扎实的活。「每个改动过的模型都验证过」要求高，「生成一份改动清单」要求低。

最强的是又清晰、要求又高。模糊的标准会让 AI 提前收工——活还没干完，就急着宣布做完了。

## 一个任务要定清的五样

（不用全写，缺哪补哪。）

- **做完什么样**：一句话，做成之后世界变成什么样（「P99 < 200ms」，不是「优化性能」）
- **拿什么证明**：测试、benchmark、截屏、命令输出……要能跑、能看、能读（见核心句）
- **不能改坏什么**：哪些东西动之前是好的，做完还得是好的（已有的测试、已有的功能）
- **只能动什么**：哪些文件、目录、资源在这个任务范围内——越界的东西留原样
- **做不下去了怎么办**：卡住的时候，带着「试过什么、卡在哪、下一步要什么」停下来问

「拿什么证明」是核心，下面三节是拿证据的具体手段。

## 怎么拿证据

按可靠程度排，从最可靠往下用：

1. **能跑的**（最可靠）：测试、编译、lint。电脑直接判对错。
2. **能看的**：改前端开浏览器看效果，改 UI 截屏对比。眼见为实。
3. **能读的**：出错就把报错完整读一遍，改完看 diff 确认只动了该动的。

证据越具体，做完没越判得准。

## 什么时候用

自动推进、跨多步、牵连多的任务——动手前先定证据。需求不清时，试着写下证据，写不出来说明还得问清楚。
