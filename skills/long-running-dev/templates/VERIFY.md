## 能跑的（最可靠）

电脑直接告诉你对错，没含糊。

```bash
# 测试。占位符，换成项目实际的命令。
<test-command>

# 编译 + lint。
<build-and-lint>
```

通过：全绿，退出码 0。

## 能看的

眼见为实。改效果类的东西，跑测试验不出来。

- 前端改动 → 开浏览器看，或截屏对比。工具：`/skill browser-use` 或 chrome-devtools CLI
- 看什么：布局没乱、交互正常、关键页面肉眼过得去

## 能读的

- 出错了：把报错完整读一遍，别扫一眼就猜原因
- 改完了：看 diff，确认只动了该动的地方

---

## 常见场景

- 前端改动 → 跑测试 + 开浏览器看
- 后端 API → 跑测试 + 编译检查
- 修 bug → 先复现，改完验证不复发
- 重构 → 跑测试，保证行为不变
- 性能 → 定一个具体的数（P99、LCP、延迟），改完对那个数
