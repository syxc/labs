# Contributing

> 适合：未来继续维护、扩展或重组这套文档的人。

感谢维护这套 Aside AI 文档包。

这份文档的目标不是形式上的开源规范，而是让后续追加内容时保持一致、可维护、可阅读。

---

## 目录分工

### `guides/`
放系统阅读型文档。

适合：
- 完整指南
- 上手指南
- 工作流或设置说明

### `templates/`
放直接复制复用型文档。

适合：
- 提示词模板
- 场景模板
- 高频常用句子收藏

### `reference/`
放查阅和定位型文档。

适合：
- 导航目录
- 避坑手册
- 纯文本索引
- 速查清单

---

## 文件命名规则

统一采用：

```text
NN-aside-ai-<slug>.md
```

例如：
- `01-aside-ai-complete-guide.md`
- `03-aside-ai-prompt-templates.md`
- `05-aside-ai-pitfalls.md`

规则：
- 用英文 slug
- 用连字符 `-`
- 保留前缀编号，保证稳定排序
- 文件名尽量短，语义明确

---

## 文档头部格式

正文类文档统一采用：

```md
[返回首页](../README.md)

# 文档标题

> 类型：Guide / Template / Reference  
> 适合：这份文档最适合谁  
> 阅读方式 / 建议用法：一句话说明如何使用
```

---

## 新增内容时建议同步更新

新增或明显修改文档后，建议顺手检查：

- `README.md`
- 所在子目录的 `README.md`
- `CHANGELOG.md`
- 必要时更新 `reference/00-aside-ai-guide-map.md`

---

## 模板写法建议

模板类文档尽量：
- 直接可复制
- 明确输入变量
- 明确边界条件
- 尽量贴近日常真实场景

优先写成这种形式：

- 用哪个网站/页面
- 完成什么目标
- 输出到哪里
- 何时停下等人确认

---

## 风格建议

- 文件名统一英文 slug
- 正文内容保持中文为主
- 标题清晰，不堆砌口号
- 少空话，多可执行建议
- 优先考虑 GitHub 阅读体验

---

## 维护原则

这套文档的核心目标是：

1. 好找
2. 好读
3. 好复制
4. 好扩展
5. 长期维护不乱
