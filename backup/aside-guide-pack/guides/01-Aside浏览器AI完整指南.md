# Aside 浏览器 AI 完整指南

这是一份面向日常使用的 Aside AI 中文实用手册，整合了：

- AI 使用指南
- 提示词模板库
- 分类提示词模板库
- 避坑手册

目标是让你把 Aside 当成一个真正能执行网页任务的助手来用，而不是普通聊天工具。

---

# 第一部分：Aside AI 到底是什么

Aside 不是单纯聊天，而是一个能在浏览器里替你执行任务的 AI Browser。

它的核心能力包括：

- 直接使用你已登录的网站
- 跨多个页面完成多步任务
- 利用当前页面、文件、历史记录和上下文
- 需要敏感操作时停下来等你确认
- 能把重复任务做成自动化 routine

所以最适合把它当成“执行型 AI 助手”。

---

# 第二部分：最重要的 AI 入口

## 1. Ask AI
这是最常用入口。

最稳的写法是每次都写清楚：
- 用哪个网站或页面
- 最终目标是什么
- 输出物是什么
- 哪一步必须停下来

### 例子
“登录 Rippling，下载我本月工资单 PDF，保存到 Downloads。如果需要 MFA 或验证码先问我。不要改任何设置。”

## 2. Side Panel
如果当前页面本身很重要，比如：
- 邮件线程
- 工单页
- 合同页
- dashboard
- 表格

那就直接从当前页面打开 side panel 发任务，并写上“使用当前页面”。

这样 Aside 才更容易基于你眼前这页做事，而不是重新乱找。

# 第三部分：Aside 最强的能力是执行任务

Aside 最适合处理这种不止一步的工作：

- 登录网站
- 搜索和点击页面
- 下载和整理文件
- 汇总多个来源信息
- 草拟回复或文档
- 走流程直到最后一步停下

### 典型任务
- 下载工资单
- 批量抓发票
- 汇总 dashboard 数据
- 从合同中提取关键日期
- 生成报销表
- 草拟客户回复

# 第四部分：最稳的提示词结构

以后尽量都用这个格式：

“使用[当前页面/网站/文件夹]，完成[明确目标]。把结果[保存位置/输出格式]。如果遇到[验证码/MFA/付款/发送]先停下来问我。不要[禁止动作]。”

### 例子
“使用当前 billing 页面，找到上季度所有 invoice，下载到 Downloads，并按日期重命名。如果遇到验证码先问我。不要修改任何 billing settings。”

---

# 第五部分：写好提示词的 4 个关键点

## 1. 点名网站或页面
不要只说“帮我处理一下”。
要说：
- “使用当前页面”
- “登录 Rippling”
- “去这个 vendor portal”
- “用 Downloads 里的文件”

## 2. 说清目标
例如：
- 下载 PDF
- 提取日期
- 生成表格
- 写草稿
- 整理摘要

## 3. 说清输出
例如：
- 保存到 Downloads
- 输出成 markdown
- 整理成表格
- 保存成 spreadsheet

## 4. 说清禁止动作
例如：
- 不要发送
- 不要提交
- 不要改设置
- 不要删除原文件

# 第六部分：Aside AI 的常见上下文来源

Aside 不只看你发的那一句话，它还会结合：

## 1. 当前页面
尤其适合 side panel 场景。

## 2. 你手动附加的上下文
比如通过 `@` 添加内容。

## 3. 浏览历史和记忆
Aside 会结合你最近使用过的站点和上下文，减少重复解释。

## 4. 文件
比如 Downloads 里的 PDF、截图、表格、文档。

# 第七部分：任务权限怎么选最稳

## Read only
适合：
- 读网页
- 提取信息
- 总结内容
- 首次试跑任务

## Guard
最适合日常。

适合：
- 下载文件
- 整理资料
- 生成文档
- 在指定目录里工作

## Full access
适合：
- 确实要跨多个目录找文件
- 本地文件处理很复杂

建议不要上来就用 Full access。

---

# 第八部分：登录能力是 Aside 的核心优势

Aside 能通过 Password Manager 和 autofill 帮你越过登录页，但不会直接把密码暴露给 AI。

它很适合：
- 登录工资系统
- 登录 CRM
- 登录供应商后台
- 登录内部业务系统

## 你通常还需要补的一步
- MFA
- 验证码
- passkey 批准
- CAPTCHA
- 身份验证

所以推荐在提示词里固定写：
“如果需要 MFA、验证码或人工验证，先停下来问我。”

---

# 第九部分：最推荐的工作方式

最稳的方式不是让 Aside 全自动一路执行到底，而是：

1. 让它登录、查找、下载、整理
2. 让它草拟内容
3. 在发送、提交、付款前停下
4. 由你做最后确认

尤其适合这些动作：
- 发邮件
- 发消息
- 发帖
- 提交表单
- 付款
- 修改设置

# 第十部分：任务跑偏时怎么纠正

Aside 支持 follow-up。

## Queue
当前 run 结束后再处理你的补充。

## Steer
立刻在当前 run 中纠偏。

### 最常用纠偏短句
- “不要走这个页面，改去 invoices 页面。”
- “不要发送，只给我草稿。”
- “改成表格输出。”
- “不要再搜网页，改用当前页面和 Downloads 里的文件。”
- “停止当前操作，不要提交或修改任何设置。”

如果它已经走偏，不要等，立刻纠正。

# 第十一部分：小问题和大任务怎么区分

## 小问题
适合：
- 总结一段文字
- 翻译一段内容
- 解释一个条款

## 大任务
适合：
- 登录并下载文件
- 跨页面搜集信息
- 处理多个文件
- 汇总成表格或文档
- 草拟回复

简单说：
- 页面局部问题，用选择工具
- 多步骤工作，用 Ask AI

# 第十二部分：Aside 自动化 routines 怎么用

如果一类工作你已经重复做过几次，就该考虑做成 routine。

## Cron routine
按时间启动新任务。

适合：
- 每周汇总
- 每日检查
- 每月下载账单

## Heartbeat routine
在原聊天上继续。

适合：
- 等通知后继续
- 等回复后继续
- 同一个任务分时推进

## 适合自动化的例子
- 每周一汇总新增 invoices
- 每天早上检查 dashboard 变化
- 每天下午整理 support inbox 草稿
- 收到某站通知后继续流程

# 第十三部分：新手最值得先练的 5 类任务

## 1. 从当前页提炼信息
“使用当前合同页面，提取续约日期、取消期限、notice period，整理成表格。”

## 2. 登录并下载文件
“登录 Rippling，下载本月工资单到 Downloads，需要验证码先问我。”

## 3. 草拟回复
“基于这个 support thread，写一个专业回复草稿，停止在发送前。”

## 4. 文件汇总
“用 Downloads 里的收据 PDF 生成一个报销表，含日期、商户、金额、支付方式。”

## 5. 周期检查
“每周一检查这个 dashboard 的变化，输出一份简短 summary。”

# 第十四部分：超短上手清单

1. 把 Aside 当执行助手，不是聊天机器人
2. 每次都点名网站或页面
3. 每次都写清楚目标结果
4. 最好写明输出位置
5. 涉及发送、提交、付款时一定写停止边界
6. 第一次跑任务优先用 Read only 或 Guard
7. 当前页很关键时一定用 side panel
8. 跑偏立刻用 Steer
9. 重复任务改成 routine
10. 遇到验证码/MFA 记得你还要补一步

# 第十五部分：通用提示词模板库

## 万能模板
“使用[网站/当前页面/文件夹]，完成[目标]。把结果[保存位置/输出格式]。如果遇到[验证码/MFA/付款/发送]先停下来问我。不要[禁止动作]。”

## 下载工资单
“登录 Rippling，下载我本月的工资单 PDF，保存到 Downloads。如果需要 MFA 或验证码先问我。不要改任何账户设置。”

## 下载发票
“登录这个 vendor portal，找到 2025 年第二季度所有 invoice 和 receipt，下载 PDF 到 Downloads，并按日期加供应商名重命名。不要修改 billing settings。”

## 客服回复
“基于这个 support thread 和相关账户页面，判断问题原因，写一封简短专业的回复草稿，并列出内部后续动作。不要发送。”

## 合同信息提取
“使用当前合同页面，提取 renewal date、cancellation deadline、notice period 和 billing owner，整理成表格，并标出 60 天内需要处理的项。”

## 报销表
“用 Downloads 里的收据 PDF 生成一个报销表，列出日期、商户、金额、支付方式和备注，保存成 spreadsheet。”

## 竞品对比
“打开并比较这两个产品页面，整理它们在价格、功能、适用对象上的差异，输出成表格。”

## 表单预填
“使用当前表单页面，根据页面内容和已有文件把能填写的字段先填好，提交前停下来让我确认。”

# 第十六部分：按场景分类的模板库

## 1. 办公协作

### 会议纪要
“使用当前页面和相关文件，把会议内容整理成纪要，包含背景、关键决定、待办事项、负责人和截止时间，输出为 markdown。不要发送给任何人。”

### 邮件草稿
“基于当前邮件线程和相关页面信息，帮我写一封回复草稿，语气专业简洁，先给我审阅，不要发送。”

### 日报周报
“根据当前页面、最近文件和相关记录，整理一份本周工作总结，分成已完成、进行中、风险和下周计划四部分。”

## 2. 销售与客户沟通

### 客户背景整理
“使用当前 CRM 页面和相关网页，整理客户背景、公司信息、最近互动记录和下一步建议，输出成简报。”

### 跟进邮件
“根据当前客户记录和会话内容，写一封 follow-up 邮件草稿，附两个可选时间，控制在 150 字以内，不要发送。”

### 会前 briefing
“使用当前客户页面，帮我准备会前 briefing，包括客户背景、已知需求、潜在 objections 和建议提问。”

## 3. 运营与支持

### 工单回复
“基于当前 support thread 和账户页面，判断问题原因，写一个客服回复草稿，并列出需要内部处理的事项。不要发送。”

### 工单分类
“使用当前工单列表，把工单按问题类型、优先级和是否需要升级分类，输出成表格。”

### FAQ 提炼
“根据当前页面内容，提炼出常见问题和标准回答，整理成 FAQ 草稿。”

## 4. 财务与行政

### 下载发票
“登录当前供应商后台，找到 [时间范围] 内的所有 invoice 和 receipt，下载到 Downloads，并按日期+供应商名重命名。不要修改任何账单设置。”

### 报销表生成
“用 Downloads 里的收据 PDF 生成报销表，列出日期、商户、金额、币种、支付方式和备注，保存成 spreadsheet。”

### 合同关键项提取
“使用当前合同页面，提取续约日期、取消期限、付款周期、金额和责任人，整理成表格。”

## 5. 研究与分析

### Dashboard 变化分析
“使用当前 dashboard，找出与上周相比变化最大的指标，写一个简短总结，并列出建议跟进项。”

### 行业资料总结
“总结当前页面和相关页面内容，提炼出 5 条最重要的信息，并说明对我有什么实际意义。”

## 6. 文件与数据处理

### PDF 批量提取
“读取 Downloads 里的这些 PDF，提取日期、名称、金额、编号等关键信息，汇总成表格。”

### 多文件汇总
“把 Downloads/[文件夹名] 里的 PDF、txt、截图和文档内容汇总，生成一份项目摘要，保存为 markdown。”

# 第十七部分：Aside AI 避坑手册

## 坑 1：提示词太泛
不要说：
- “帮我处理一下这个”
- “帮我整理财务”
- “帮我回一下客户”

要改成：
- 指定站点
- 指定目标
- 指定输出
- 指定边界

## 坑 2：不给停止边界
如果不写清楚，AI 可能走到发送、提交、修改设置那一步。

建议固定加：
- “不要发送”
- “提交前停下”
- “不要修改设置”
- “只生成草稿”

## 坑 3：把执行任务写成聊天问题
Aside 强在执行，不只是解释。

## 坑 4：当前页很重要却没用 side panel
这样它可能重新搜索，跑到别的页面去。

## 坑 5：第一次就给 Full access
先用 Read only 或 Guard 更稳。

## 坑 6：忘了它会卡在 MFA、验证码、passkey
这通常不是失败，是在等你。

## 坑 7：它跑偏了还不及时纠正
立刻用短句 Steer。

## 坑 8：不写输出格式
一定写清是：
- 表格
- markdown
- spreadsheet
- PDF

## 坑 9：不写保存位置
特别是下载类任务，一定写 Downloads 或具体路径。

## 坑 10：一个提示词塞太多目标
最好拆成两步。

## 坑 11：高风险动作不先做草稿
发邮件、发帖、付款、提交表单前都应该先停下。

## 坑 12：把它当全自动，不留复核
最稳模式还是：AI 做前 80%，你做最后确认。

# 第十九部分：如果你只记住一句话

**把 Aside 当成一个执行型浏览器助手来下指令，而不是普通聊天机器人。**

你越像在给一个会操作网页的助理分配任务，它通常表现越稳。
